3D Reader — use from AI assistants and scripts

Français plus bas · Open the reader

3D Reader measures a 3D model: the real volume of material (exact for STEP/IGES/BREP CAD files, enclosed volume for meshes), surface area, axis-aligned and minimum oriented envelope, fill ratio, centre of mass, mass from a density, per body. It runs entirely in the browser (no upload to a server). Formats: STEP, STP, IGES, IGS, BREP, STL, OBJ, PLY, OFF, GLB, glTF, 3MF, DAE. Units of results: mm, mm², mm³, g.

1. Agent that can open web pages (browser automation)

If the model is reachable at a public URL that allows cross-origin downloads (CORS: for example raw.githubusercontent.com), open:

https://alexdevanssay-cmyk.github.io/3D-reader/?url=<URL of the 3D file>&report=1

Wait until <body data-status="done"> (or "error", with the message in data-error), then read either:

  • the plain-text report in <pre id="reader3d-report"> (shown in the page with report=1), or
  • the JSON in <script id="reader3d-result" type="application/json">.

The first CAD file downloads the CAD engine (about 13 MB): allow up to a minute.

2. Agent that was given the file itself

Open the reader and upload the file through the file input #file-input (button “Open file…”), or run JavaScript in the page:

const result = await reader3d.analyze(fileOrBlobOrUrl, { name: "part.step" });
console.log(reader3d.report());   // plain-text summary

Then read the results as above, or click Excel, CSV or JSON to download them.

3. Agent or script that can run Python

pip install "git+https://github.com/alexdevanssay-cmyk/3D-reader"
reader3d analyze part.step --json

Python 3.11+. Same results as the browser (same OpenCascade exact integration).

Link parameters

ParameterMeaning
urlAddress of the 3D file to analyse (must allow CORS).
nameFile name to use when the URL does not end with one (its extension selects the format).
report=1Show the results as plain text at the top of the results panel.
exportjson, xlsx or csv: download the results when done.
thickness=1Also compute the wall thickness of the closed bodies (inscribed-sphere method): thickness {method, min, median, max} in mm in the JSON, per body and for the whole model, and a wall_thickness line in the report. The exports always include it.
unitUnit of mesh files: mm, cm, m, in, ft (default: auto).
qualityDisplay tessellation of CAD files: coarse, normal, fine (does not change the volume).
langfr or en.

3D Semantic JSON

V3 B-Rep evidence: cylindrical candidates now carry boundary evidence (wire_count, edge_count) and can be promoted to possible_through_hole or possible_bore only when the geometric and boundary signals agree: possible_through_hole needs a face with the material outside it ("reversed") bounded by two edges, and still needs topology confirmation, since a blind hole gives the same signals. The semantic layer keeps uncertainty explicit.

V2 feature layer: CAD bodies may now expose analytic surfaces (cylinder radius/axis/centre, cone angle, sphere radius, torus radii) and conservative feature candidates such as possible_hole_or_bore. A candidate always carries a confidence, a detection method, and may require topology confirmation. Each analytic surface gives the orientation of its face ("forward" or "reversed"); a plane's normal points out of the material, and center_mm is the middle of the face's UV bounds: on its surface, not always on the face (on the axis for a cylinder or a cone). A cone's ref_radius_mm is its radius at axis_origin_mm.

The AI-facing semantic contract is exposed as window.reader3d.semantic and in #reader3d-semantic-result, which is written once the page is idle after each result (null until then). Each body has the source_index of the body in the file, the index that reader3d.setSelection takes. It is versioned independently from the raw measurement result: schema = 3d-semantic-json, schema_version = 1.0 and feature schema 10.0. Features expose stable IDs (scoped by body since 10.0), evidence status and evidence counts. It contains model/body metrology, topology (of the welded mesh, given by the in-browser engine: null for a result of the Python engine), principal axes and conservative geometric feature candidates. Tessellation buffers are deliberately excluded from this payload.

Semantic feature candidates

Features carry evidence-quality metadata and stable feature identifiers, alongside the provisional candidates for holes, tapered transitions, fillets, chamfers, and repeated cylindrical patterns. Candidates include explicit evidence and needs_topology_confirmation when design intent is not proven.

Relations

Each semantic body may expose analytic surface relations separately from inferred feature candidates. Relations describe geometric evidence; feature candidates interpret that evidence and may remain uncertain.

V5 manufacturing semantics

The semantic JSON now also exposes a manufacturing layer per body. It contains candidate manufacturing operations, geometric tool-axis/setup candidates, a deterministic candidate operation sequence, functional wall-thickness metadata when the Reader already provides it, and conservative DFM recommendations. These values are explicitly candidates rather than executable toolpaths: stock, fixture, machine limits and exact accessibility are not inferred from geometry alone.

V6 manufacturing planning semantics

Feature schema 9.0 adds a deterministic planning layer on top of V5 manufacturing candidates. Each body may expose manufacturing_plan with compatible tool-axis setup candidates, operation dependencies, a deterministic planned order, readiness signals, and explicit unresolved constraints. V6 does not perform stock/fixture collision analysis, machine kinematics, tool selection or cutting-parameter generation; it is planning evidence, not CAM output.

V7 AI reasoning context

The semantic JSON can be compiled into a compact, evidence-linked context specifically intended for an LLM. This layer does not add geometry or upgrade provisional detections.

const context = reader3d.aiContext({ task: "manufacturing_analysis" });
const featureContext = reader3d.aiContext({
  task: "feature_analysis",
  featureIds: ["body-0/feature-..."]
});

Supported tasks are general, feature_analysis, manufacturing_analysis, dfm and planning. The context preserves feature/relation IDs (scoped by body, e.g. body-0/feature-1a2b3c4d, body-0/relation-3), evidence, confidence, provisional status and unresolved manufacturing constraints. The LLM must treat provisional features as hypotheses, cite the supplied evidence for conclusions, preserve units and never invent dimensions. V7 remains a reasoning context layer, not an LLM itself and not a CAM generator.

En français

Pour qu'une IA mesure un modèle 3D avec ce lecteur :

  • Le fichier est en ligne (adresse publique autorisant le CORS, par exemple un dépôt GitHub) : l'IA ouvre https://alexdevanssay-cmyk.github.io/3D-reader/?url=<adresse du fichier>&report=1&lang=fr, attend data-status="done" puis lit le rapport texte ou le JSON.
  • L'IA a reçu le fichier et pilote un navigateur : elle ouvre le lecteur et charge le fichier par le bouton « Ouvrir un fichier… » (ou await reader3d.analyze(fichier)), puis lit les résultats ou télécharge l'Excel.
  • L'IA exécute du Python : pip install "git+https://github.com/alexdevanssay-cmyk/3D-reader" puis reader3d analyze piece.step --json.
